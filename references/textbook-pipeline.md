# 分卷写作流水线

先建立 outline.md、symbols.md、sources.md、verification.md，记录目标、读者基础、统一符号、来源状态、验证与缺口。正文分别写入 parts/，主文件仅含导言、目录与 input。Markdown 使用同样的分卷逻辑。

| 分卷 | 任务 | 证据 |
| --- | --- | --- |
| 01 基础 | 全书地图和前置概念 | 定义及起点例子 |
| 02 问题 | 朴素办法为何不够 | 失败案例 |
| 03 方法 | 新方法改变什么 | 定义、假设、机制图 |
| 04 机制 | 每一步发生什么 | 完整推导与边界 |
| 05 实操 | 能否亲手重现 | 经核验演算、适用时的代码 |
| 06 边界 | 何时不适用 | 同条件对比、反例、阅读导航 |

每卷独立落盘后继续。合并时补过渡、去重、统一符号。不因单次输出限制将后半本压成大纲。

技术教材约 25–35 页，侧重机制、手算、实现与数学。40 页通识档目标约 40 页，42–47 页可接受，必须统计实际 PDF。原技能纯叙事 30,000 字以上、目标 35,000 字、约 3–4% 数字密度保留为诊断参考，统计排除代码、TikZ、表格与教学盒。冲突时报告取舍，不缩字或写空话凑页。

技术长篇通常 5–6 幅解释图，每个适合图解的分卷至少一幅；正文表格通常不超过 3 张，附录除外。

## 附录四件套

1. 阶梯推导：直觉、具体演算、严格定义。人文改为论证与史料批判。
2. 名词速查：40 页档通常 25–35 条，不依赖未定义术语。
3. 自测与答案：40 页档通常 8–10 题，含迁移与错误分析。
4. 来源导航：已核实论文与 DOI；无 DOI 列作者、标题、出版社或官方 URL。人文区分原始史料和现代研究。

验证报告列文件、PDF 实测页数、编译结果、实际检查页码、演算复核、代码运行环境与输出、引用核实日期、未完成项。原作者的历史成绩不当成本次验证。
