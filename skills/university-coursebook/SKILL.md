# University Coursebook · 40 页零基础课本

> 面向从零入门的长篇课程：类比只给难点，正文保持克制的大学讲义语气，并以可编译 PDF 完成交付。

## 这个技能解决什么问题

写硬核技术长文时最容易犯的三个错：
1. **默认读者有背景知识**——上来就是「注意力机制」「$\mathrm{SE}(3)$ 等变」「扩散模型」，高中生（以及跨领域的聪明人）在第 3 页就丢了；
2. **一篇文章塞进一个巨型 .tex**——写到第 800 行时上下文爆掉、结构失控、改一处要通读全文；
3. **编译踩坑重复踩**——`equation` 里换行、`\texttt` 长 DOI 溢出、伪代码包错环境……每一篇都要重新debug一遍。

本技能把已在 4 篇文章上验证过的**工作流、教学规范、编译硬约束**固化下来，让新文章直接进入「写内容」而不是「调格式」。

---

## 一、交付标准（硬指标）

| 维度 | 标准 |
|---|---|
| 篇幅 | **40 页左右**（A4，实测 42--47 页可接受；对应约 1700--2000 行 LaTeX） |
| 读者 | **假设只读到高中**，不假设任何领域背景 |
| 拼装 | 主文件 + `parts/` 分卷目录 + `\input` |
| 编译 | `tectonic` 一次通过，**零致命错误**，显著 Overfull（≥10pt）清零 |
| 类比密度 | 全文 **15--25 个**「生活类比」盒，**只覆盖难点概念**，且允许**多个难点讲完后集中打包**在一个盒里（一个盒可含 2--4 个场景） |
| 附录 | 必须含**四件套**：阶梯数学 / 名词速查表 / 自测题与答案 / DOI 文献清单（若主题涉及论文） |

## 二、工作流（分卷流水线）

```
① 定角度  →  ② 建任务清单  →  ③ 建 parts 目录  →  ④ 逐 part 写
        →  ⑤ 主文件 \input 拼装  →  ⑥ tectonic 编译 + 自修复  →  ⑦ 交付
```

### ① 定角度：先问，再写

主题往往是宽泛的（「AI4S」「世界模型」「具身智能 VLA」）。**写错方向 = 十几页白费**，所以动笔前用 `AskUserQuestion` 锁一个角度，给 3--4 个选项，把推荐项放第一个并标注「（推荐）」。

推荐顺序的原则：**优先选与已有文章互补、且数学/故事性最浓的那条线**。

### ②③ 建任务与目录

```bash
mkdir -p <文章目录>/<主题>_parts
```

用 `TaskCreate` 建 2--3 个任务：撰写长文 / 编译自修复 / （可选）验证手算数字。

### ④ 逐 part 写（本技能的核心节奏）

**每个 part 一个 `Write` 调用，250--320 行**。不要试图一次写完 2000 行。

推荐分卷（6 个 part）：

| 文件 | 内容 | 目标行数 |
|---|---|---|
| `p1_basics` | 第 0 章开场 + 最底层的 2--3 个先修概念 | ~250 |
| `p2_<核心对象>` | 主题主角是什么、它要解决什么问题 | ~290 |
| `p3_<方法/工具>` | 工具箱与方法学 | ~230 |
| `p4_mechanism` | 机制细节，逐层拆解 | ~290 |
| `p5_handson` | 手算 + 可运行代码 | ~220 |
| `p6_frontier` | 全景对比、避坑、附录四件套 | ~320 |

### ⑤ 主文件拼装

主文件只放 preamble + 目录 + 一串 `\input`，**不放正文**（见 `assets/latex-template.tex`）。

### ⑥ 编译与自修复

```bash
cd <文章目录> && tectonic -X compile <主文件>.tex --outdir . > /tmp/x.log 2>&1; echo "EXIT=$?"
grep -E "Missing \\\$|Undefined control|! LaTeX|! Package|Giving up|unrecoverable|Runaway" /tmp/x.log
grep "Overfull" /tmp/x.log | grep -vE "\([0-9]\.[0-9]+pt|\([0-9]pt\)"   # 筛出 ≥10pt 的显著溢出
```

**页数码**：PDF 用压缩对象流，grep 不到，需解压统计：

```python
import re, zlib
data = open("<主文件>.pdf", "rb").read()
c = 0
for m in re.finditer(rb'stream\r?\n(.*?)\r?\nendstream', data, re.S):
    try: dec = zlib.decompress(m.group(1))
    except: continue
    if b'/Type' in dec and b'Page' in dec:
        c += len(re.findall(rb'/Type\s*/Page\b(?!s)', dec))
print("pages:", c)
```

## 三、教学规范（这是「高中生能读懂」的关键）

### 1. 类比只覆盖难点，且可集中打包出现（2026-08-29 修订）

**原则 A：类比是稀缺资源，只给真正难的概念。** 读者读到高中水平，很多概念本身不构成理解障碍（如「自由度 = 能独立变化的个数」「坐标系 = 描述位置的方法」），这类概念用一两句朴素的话定义即可，**不要**给类比盒。类比盒只留给那些「不类比就很难抓住直觉」的难点，例如：维度灾难/自由度爆炸、欠驱动与腱驱动、误差累积、动作分块、扩散去噪、马尔可夫性、稀疏奖励、折扣因子、探索 vs 利用、PPO 小步更新、域随机化、摩擦锥、卡尔曼滤波、接触不连续。检验标准：**这个概念，一个高中生第一次见会不会懵？不会懵就不配拥有类比盒。**

**原则 B：多个难点讲完后，集中打包类比一次。** 类比盒不要一个难点跟一个（否则全文被橙色盒子打断，节奏差）。正确节奏是：连续讲完 2--4 个难点后，用一个 `tipbox`（内部用编号或分段）一次性给出这几个难点的生活类比。例如讲完模仿学习的三个方法（行为克隆/动作分块/扩散）后，用一个「模仿学习三连」盒：复读机游戏（误差累积）、背课文整段背（动作分块）、雪花照片倒放（扩散去噪）。读者能在一次阅读里横向对比三个概念，效果优于三个分散的盒子。同一个盒子里多个场景要明确标注「场景一/场景二/场景三」或分段，防止混淆。

**原则 C：tipbox 标题必须是平静的内容短语或意象，禁止元描述（2026-08-29 修订）。** 标题写「复读机、背课文与雪花照片」「端稳杯子，闭眼摸鼻」「指尖顶住桌面的瞬间」这类有画面感的名词短语，像讲义里的小标题。**禁止**写「生活类比 · X」「集中类比 · X（N 个难点一次打包）」这种暴露写作策略的元描述——「打包」「类比」是作者的动作，不是内容，读者一眼就看出是 AI 写作习惯。同理，正文里禁止「我们会把类比集中打包」「一个加餐小节」这类自我说明。

已验证好用的类比库（可直接复用或照此风格新造）：

| 抽象概念 | 类比 |
|---|---|
| 原子/化学键 | 乐高积木与连接点 |
| 能量最低原理 | 球滚下坡 / 站着比坐着累 |
| 活化能 | 翻山 vs 走隧道 |
| 形状决定功能 | 钥匙与锁 |
| 构象搜索爆炸 | 试遍所有组合要多久（宇宙年龄的 $10^{18}$ 倍） |
| 同源建模 | 抄作业（没相似题型就崩） |

| 三角不等式 | 三根木棒能不能围成三角形 |
| 等变性 | 看地图（转地图，距离不变、坐标跟着转） |

### 2. 由简到繁，逐个击破

- 正文只用**初中到高中**的数学（勾股定理、二次方程、指数）；
- **所有**群论、流形、变分推断、ELBO 等硬核内容一律收进**附录「阶梯 2」**，并在正文明确标注「第一次读可以跳过」；
- 每篇（part）末尾必须有 `\begin{stepbox}{本篇小结（你已会什么）}`，用 bullet 列出本篇交付的能力，并以「下一篇我们要……」勾住读者。

### 3. 第 0 章必须给「全书地图」

用编号列表逐篇说明「这一篇解决什么、读完你能干什么」，让读者在开始前就知道路线。

### 4. 语气：Stanford 讲义风（2026-08-29 修订）

整体语气要像 Stanford CS 课程的 lecture notes（CS229 / CS231n / CS224n 的讲义）：**平静、克制、专业**。判断标准：把任意一段读给一个聪明的高中生，他应该觉得「这是一本正经教科书在教我」，而不是「一个 AI 在给我讲课」。

**禁止清单（AI 腔 / 元叙述 / 口语化）**：
- 写作策略自我说明——「我们会把类比集中打包」「三个难点一次打包」「一个加餐小节」「不铺张浪费」「接下来我们看看」「值得一提的是」等谈论「作者自己怎么写」的句子，一律删或改写成内容本身；
- 「生活类比 ·」「集中类比 ·」等标签前缀（原则 C）；
- 口语化感叹与套话——「很好记」「你可能好奇」「没错」「就是这么简单」；
- 冗余连接词——「需要注意的是」可删则删；
- 破折号滥用——连续多个「——」排比，改为陈述句。

**允许**：交叉引用（「第 X 章会展开」）、optional 标注（「第一次读可以跳过」）、平静过渡句（「先看一个例子」「用五步讲清楚」）。标题一律用内容短语或意象（原则 C）。

### 5. 手算章节的数字必须真算过

凡声称「手算」的章节，先用 Python 把数字算一遍再写进文章，**禁止凭感觉写数字**。已验证的数字（如 $k=1400\ \mathrm{s^{-1}} \Rightarrow \Delta G^{\ddagger}\approx13.2$ kcal/mol）才写进正文。

## 四、附录四件套（缺一不可）

1. **附录 A · 阶梯 0→1→2**：阶梯 0 三句话直觉 / 阶梯 1 手算闭环 / 阶梯 2 严格数学表述（含群与等变性定义、流形扩散、过渡态理论与隧穿校正等）。
2. **附录 B · 名词速查表**：`p{3.0cm}p{8.6cm}` 两列表，25--35 条，每条一句话解释。
3. **附录 C · 自测题与答案**：8--10 题，配完整参考答案。
4. **附录 D · 已核实 DOI 文献清单**：按主题分 2--5 张表（见下节纪律）。

## 五、DOI / 引用纪律（学术硬伤防线）

**用户明确要求附 DOI 时，绝不能凭记忆写 DOI——编错就是学术硬伤。**

1. 动笔前用 `WebSearch` **逐条核实**关键文献的 DOI；
2. 从搜索结果里顺手采集同主题的其它已验证 DOI（综述的参考文献列表是金矿）；
3. 在文章开头用 `tipbox` 声明：「本文引用的全部文献 DOI 均已逐条联网核实（核实日期：YYYY-MM-DD），汇总于附录 D。**凡本文未给出 DOI 的条目，均为尚未核实，请读者自行查证后再引用。**」
4. 排版必须用可断行、可点击的写法（见下节编译约束）。

## 六、编译硬约束（4 篇文章累积的血泪清单）

> 以下每一条都曾真实导致编译失败或排版溢出。写代码时直接遵守，不要等报错。

### 致命级（导致 XeTeX 崩溃、PDF 不产出）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 数学符号裸用在正文（如 `向量场\approx常数`） | 必须包在 `$...$` 内 |
| 2 | 文件名/代码标识符的**下划线**写在正文（如 `vla_flow_matching`） | `\texttt{vla\_flow\_matching}`；长词再加 `\-` 断点 |
| 3 | 伪代码命令包进 `tcolorbox` | 必须 `\begin{algorithm}` + `\begin{algorithmic}[1]`，盒子只能放算法**外面** |
| 4 | `algpseudocode` 用全大写 `algorithmic` 风格 | 用混合大小写：`\Require \Ensure \State \Repeat \Until \For \EndFor` |
| 5 | 用 `\TO` | 该包未定义，写 `\For{$i=0$ \textbf{to} $N-1$}` |
| 6 | 附录用 `\section*{附录…}` | 用 `\appendix`，其后 `\section` 自动变 A/B/C |
| 17 | 正文用**反引号**包裹代码标识符（如 `` `no_slip` ``） | 反引号在正文只是引号字符，含 `_` 时报 `Missing $`；一律写 `\texttt{no\_slip}`（下划线必须转义） |

### 溢出级（不致命但文字冲出页面）

| # | 坑 | 正确做法 |
|---|---|---|
| 7 | 多行算式写进 `equation` | `equation` 不支持换行；改用 `align` + `\nonumber`（曾溢出 94pt） |
| 8 | 超长 `\texttt{...}` 无法断行 | 用 `\-` 插断点；**长 DOI/URL 直接用 `\href{https://doi.org/<DOI>}{\nolinkurl{<DOI>}}`** |
| 9 | 窄 `p{}` 列放长 DOI | DOI 列给到 **≥5.9cm**；`\texttt` 换 `\nolinkurl` 后可从 27 处 Overfull 降到 6 处且全 <10pt |
| 10 | 表格总宽超版心 | 三列预算：`0.8 + 7.9 + 5.9 = 14.6cm`（版心 16cm），列宽含 `\tabcolsep` 要留余量 |
| 18 | **超过一页容量的长 `tabular` 跨页**（如 40 行名词表） | 跨页产生 Overfull \vbox（实测 19.5pt）；按主题拆成 2 个表，每个 ≤25 行 |

### TikZ 级

| # | 坑 | 正确做法 |
|---|---|---|
| 11 | 并排子图用 `xshift` + 外层 `scale` | 两者复合会算错位置导致**图形重叠**；改为**同一坐标系叠加显示** |
| 12 | `\foreach` 配 `gray!55!white` / `above left=4pt` | 偶发 TikZ 解析失败；改用显式 `\draw` 序列 + `gray!50` / `above left` |
| 13 | 方框外单独定位标题文字 | 标题与正文写在**同一个 node 的 `{}` 内**，配 `text width` 防出界 |
| 14 | 节点坐标超出 ±5（x）/ ±3（y） | 配合 `scale=0.9` 控制，先估算总宽再落笔 |
| 19 | 极坐标参数里用 `\def` 宏（如 `+(\ttone:0.9)`、`arc (0:\ttone:0.9)`） | 偶发 `Undefined control sequence`（`\ttone` 在极坐标里无法展开）；坐标/角度直接写数值或用 `{...}` 包裹 |

### 内容级

| # | 坑 | 正确做法 |
|---|---|---|
| 15 | 中文写入出现乱码（如「要知??药物」） | 交付前 `grep -n "��"` 扫一遍 |
| 16 | 声称代码「可直接跑通」但本机没装依赖 | 本机**无 torch/numpy**；要么写成**纯标准库可实跑**，要么明确标注「参考实现，需 `pip install torch`」——**不要谎称已验证** |

## 七、代码章节原则

- **优先写纯标准库 Python**（`math` 即可），这样能在本机**真的跑一遍**验证输出，文章中就可以诚实地说「已实跑验证」；
- 若必须用 PyTorch，标注「参考实现（需 `pip install torch`），未实跑」，并逐行讲解代码在干什么（讲思路，不讲语法）；
- 代码后必须有**逐行讲解**和**预期输出说明**。

## 十、验收指标的两个陷阱（2026-08-29 第 8 篇实测，务必照做）

### 陷阱一：数字密度会被 TikZ 坐标与代码块撑高

直接用「正文字符里的数字占比」当脱水指标会被严重误导：TikZ 图里满是 `(-3.4, 1.1)`、`minimum width=2.6cm`
这类坐标与尺寸，**图越多，密度看起来越高**。实测同一篇文章：含 TikZ 时密度 7.00%，剥掉 `tikzpicture` 后只剩 3.69%。

**正确测法（验收一律用这个）**：剥离 `tipbox/stepbox/exbox/thinkbox` + `lstlisting` + `tikzpicture` + `tabular`
之后，再统计剩余「纯叙事文字」的字数与数字占比。

| 文章 | 含图代码密度 | **纯叙事密度（正确指标）** |
|---|---|---|
| 蛋白质篇（好评基准） | 3.67% | **3.15%** |
| DNA v1（回退） | 4.35% | 2.86% |
| DNA v2 | 4.21% | 1.77% |
| DNA v3 | 7.00% | **3.69%** |

**基准线：纯叙事密度 3–4%**（低于 2% 叙事太空，高于 5% 在堆数字）。
手算/代码章允许单独飙到 10%+，那是章节目使然，不计入整体。

### 陷阱二：「厚实感」的真实来源是纯叙事字数，不是总页数

配图会**挤占散文篇幅**。实测蛋白质篇纯叙事 38355 字 / 5 幅图；DNA v3 纯叙事 23515 字 / 11 幅图，
页数却相近（47 vs 48）。**读者主观感受到的「厚实」，来自纯叙事字数。**

**基准线：纯叙事 ≥30000 字（目标 35000+）。**
图多导致纯叙事不足时，正确做法是**加叙事段落**（史料故事、流程故事、案例走查），而不是删图——
**图多从来不是问题，「有图没话」才是。**

### 附：代码验证又抓到一个 bug（重申必须真跑）

`sum(p * log2(p/0.25) for p in probs if p > 0)` 在 `probs` 是 dict 时会报
`TypeError: '>' not supported between 'str' and 'int'`——**迭代 dict 得到的是键不是值**，必须写 `probs.values()`。
**声称能跑的代码，必须真的跑一遍再写进文章。**
